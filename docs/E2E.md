# Сквозное шифрование сообщений

Текст сообщений в личных чатах, группах и «Избранном» шифруется в браузере отправителя и расшифровывается только на устройствах участников чата. Сервер хранит шифротекст (`messages.e2e`), поле `body` у таких сообщений пустое.

## Как это устроено

- **Устройство** — профиль браузера, в котором выполнен вход в аккаунт. При первом запуске создаются две пары ключей P-256 (WebCrypto): ECDH для получения и ECDSA для подписи. Закрытые ключи создаются неэкспортируемыми и хранятся только в IndexedDB этого браузера (`cipherion-e2e`). Сервер получает открытые ключи (`POST /api/e2e/devices`) и привязывает устройство к текущему сеансу.
- **Отправка.** Клиент запрашивает открытые ключи всех устройств участников с активными сеансами (`GET /api/e2e/keys?chat=…`), шифрует текст случайным ключом AES-256-GCM (с привязкой к ID чата), а этот ключ — отдельно для каждого устройства через ECDH с одноразовым ключом + HKDF-SHA-256. Конверт подписывается ECDSA-ключом отправляющего устройства.
- **Получение.** Клиент проверяет, что подпись сделана устройством автора сообщения, и только потом расшифровывает. Подделанный или повреждённый конверт показывается как «Не удалось расшифровать или проверить сообщение».
- Повторная отправка из офлайн-очереди использует тот же конверт, поэтому идемпотентность по `clientMessageId` сохраняется. Правка зашифрованного сообщения шифруется заново; открытым текстом её изменить нельзя. Пересылка шифруется заново для чата назначения.

## Код безопасности

Меню чата → «Шифрование» показывает код безопасности: хеш открытых ключей всех устройств участников. Если коды у собеседников совпадают, сервер не подменил ключи. Код меняется, когда кто-то входит с нового устройства.

## Ограничения

- Шифруются текст, вложения до 200 МБ, тексты опросов и чек-листов (вопрос, варианты, описание, пояснение викторины, добавленные пункты), стикеры из встроенных наборов, цитаты, волна голосовых и облачные черновики. **Не** шифруются: отложенные (серверные) сообщения и опросы, стикеры из пользовательских наборов (сервер проверяет доступ к их файлам), голоса в опросах (сервер видит номера выбранных вариантов).
- Каналы не шифруются. Чаты с детскими аккаунтами не шифруются, потому что для них действует серверный семейный фильтр.
- Если у кого-то из участников ещё нет ни одного устройства с ключами (не открывал обновлённое приложение), сообщения в этом чате отправляются без сквозного шифрования, а в окне «Шифрование» об этом написано. Сообщения без шифрования не отмечаются замком.
- Новое устройство (вход в другом браузере, очистка данных сайта) само не может прочитать сообщения, отправленные до его появления. Их открывает перенос истории (ниже).
- Нет forward secrecy на уровне сессий (как в Double Ratchet): компрометация закрытого ключа устройства раскрывает все сообщения, адресованные этому устройству.
- Сервер видит метаданные: кто, кому, когда, размер сообщения, список устройств-получателей и ID кастомных эмодзи.
- Расшифрованная история кешируется в IndexedDB этого браузера (`cipherion-history`), как и раньше.
- Группы с фильтром ссылок или запрещённых слов (защита от спама) не шифруются: сервер должен читать текст. Проверка новых участников работает с шифрованием.
- Серверный поиск, AI-ассистент и push-превью не видят текста зашифрованных сообщений; push показывает «🔒 Зашифрованное сообщение». Поиск внутри открытого чата работает на устройстве.
- Код загружается с того же сервера: оператор, способный изменить JavaScript приложения, может обойти шифрование. Это общее ограничение веб-мессенджеров.


## Вложения

Фото, видео, голосовые, кружочки и файлы до 200 МБ в зашифрованных чатах шифруются на устройстве отправителя
отдельным случайным ключом AES-256-GCM (дополнительные данные `cipherion-file-v1`). На сервер уходит
непрозрачный файл типа `application/x-cipherion-sealed` с именем `encrypted.bin`. Ключ, вектор
инициализации, настоящее имя, тип и размер файла кладутся в поле `f` зашифрованного текста сообщения
(`{b, t, f:{k, iv, n, m, s}}`), поэтому открыть файл могут только устройства участников чата.
Сервер принимает такой файл только вместе с зашифрованным сообщением и не даёт переслать его в чат без шифрования.
Файлы больше 200 МБ и вложения в чатах без шифрования (каналы, чаты с ботами и детскими аккаунтами) отправляются как раньше.
Сервер не может пережать зашифрованное видео, поэтому такие видео весят больше.

## Что видит сервер

- Получателей @упоминаний (список id нужен для уведомлений), тему форума, таймер автоудаления.
- Адрес ссылки, если у отправителя или получателя включены превью ссылок: превью собирает сервер,
  чтобы сайт не узнал IP-адрес читателя. Превью выключаются в «Настройки → Чаты».
- Координаты геопозиции в зашифрованных чатах сервер не видит: они шифруются как текст.

## Перенос истории на новое устройство

У каждого аккаунта есть **ключ истории** — случайный ключ AES-256, который знают только устройства аккаунта. Его создаёт самое старое устройство с активным сеансом (или любое — по явной кнопке).

- **Гранты.** Устройство, которое открыло зашифрованное сообщение, заворачивает его ключ содержимого ключом истории (AES-GCM, дополнительные данные `cipherion-grant-v1|<id сообщения>`) и отправляет на сервер (`POST /api/e2e/grants`). Раз в три дня приложение проходит по последним страницам всех чатов, чтобы гранты были и для давно открытых сообщений; это же можно запустить вручную («Подготовить историю для переноса»).
- **Новое устройство** получает ключ истории и открывает старые сообщения через гранты. Подпись автора проверяется так же, как раньше.
- **Через QR-код.** Новое устройство создаёт одноразовую пару ECDH P-256. Её открытый ключ входит в QR-картинку (`#qr-login=…&k=…` при входе по QR или `#e2e-transfer=…&k=…` в «Устройства → Перенос истории»). Старое устройство сравнивает ключ из картинки с ключом, который отдал сервер, и заворачивает ключ истории для него (ECDH + HKDF-SHA-256 + AES-GCM). Сервер подменить ключ не может: при сканировании ключ берётся из картинки, при ручном вводе кода сверяются проверочные цифры на обоих экранах.
- **Резервная копия с паролем.** Ключ истории шифруется ключом из пароля (PBKDF2-SHA-256, 600 000 итераций, случайная соль) и хранится на сервере. Пароль на сервер не передаётся; забытый пароль восстановить нельзя.
- **Черновики** шифруются ключом истории (`e2d1:…`), поэтому их видят все устройства аккаунта, но не сервер.
- Если все старые устройства потеряны, «Я потерял все старые устройства» создаёт новый ключ: старые сообщения останутся нечитаемыми на новых устройствах.

Ограничения: сервер видит, для каких сообщений есть гранты, и хранит резервную копию (её стойкость равна стойкости пароля). Ключ истории хранится в IndexedDB устройства в извлекаемом виде, потому что его нужно уметь передать.
