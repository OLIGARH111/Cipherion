# Эксплуатация

## Один сервер

1. Установите Node.js 24+ и скопируйте исходники.
2. Назначьте приложению отдельного пользователя ОС и постоянную директорию `DATA_DIR` с доступом только этому пользователю.
3. Разместите приложение за HTTPS reverse proxy. Установите `PUBLIC_ORIGIN` в точный внешний origin и `COOKIE_SECURE=1`. Для Render Blueprint уже включает `TRUST_PROXY=1`; не включайте его на сервере, который не находится за доверенным proxy.
4. Проксируйте все маршруты, включая `/api/events`, без буферизации SSE. Read timeout должен быть больше 20 секунд; heartbeat отправляется каждые 20 секунд.
5. Для вложений разрешите запросы до 50 МБ. API использует буфер в памяти, поэтому ограничивайте параллельные загрузки на reverse proxy.
6. Запустите один процесс под supervisor. Несколько процессов не разделяют карту SSE и активных звонков.
7. Настройте TURN для звонков между сетями. Для крупных групп замените mesh на SFU.

Пример Nginx внутри уже настроенного HTTPS virtual host:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_buffering off;
    proxy_read_timeout 90s;
    client_max_body_size 50m;
}
```

Встроенный лимит запросов считает прямой IP сокета. За proxy несколько пользователей могут делить один лимит. Перед публичным запуском добавьте контролируемую обработку доверенного proxy и распределённые лимиты. Не доверяйте произвольному `X-Forwarded-For` из интернета.

## Резервные копии

`DATA_DIR` содержит `cipherion.sqlite`, WAL-файлы и `media/`. Для согласованной офлайн-копии остановите приложение и скопируйте всю директорию. Для online backup используйте SQLite backup API в отдельной операционной процедуре. Проверяйте восстановление на отдельном экземпляре.

Медиа, не прикреплённые к сообщениям, пока не удаляются автоматически. Настройте мониторинг диска. Удаление сообщения скрывает его и закрывает доступ через сообщение; это не гарантирует физическое удаление файла, используемого аватаром, фоном или пересылкой.

## Перед публичным production-запуском

- Добавить подтверждение контакта / восстановление пароля, MFA, модерацию злоупотреблений и квоты хранилища.
- Проверить камеру / микрофон / воспроизведение на целевых iOS Safari, Android Chrome и desktop-браузерах.
- Провести нагрузочный тест, независимый security review и проверить реальные TURN-сценарии.
- Создать продуктовые документы о конфиденциальности, условиях использования и сроках хранения для фактического оператора сервиса.
- Подключить фоновые push-уведомления, если требуется работа при закрытой вкладке.

Этот репозиторий не включает публичное развёртывание, внешние учётные записи, платные сервисы или секреты.
