# Доставка, оформление и стикеры — рабочий выпуск 30 сентября

Это проверяемый этап большой переработки, **не завершение всего задания VIP 2.0**. Код не подтверждает работу установленной PWA на физическом iPhone до проверки на развёрнутом HTTPS-сервере.

## Что изменено

- Сообщения сохраняются в SQLite до ответа клиенту. Идемпотентность по `(user_id, client_id)`, журнал изменений с курсором, восстановление через существующее авторизованное SSE-соединение, локальная IndexedDB-очередь текста, файлов, записей и стикеров. Повтор после потерянного ответа не создаёт второе сообщение. Локальная очередь отправляется при следующем открытии приложения/восстановлении связи; фоновой отправки из полностью закрытого браузера здесь нет.
- Серверная очередь Web Push создаётся триггером в транзакции сообщения. Отдельные подписки устройств, повторные попытки, удаление 404/410, привязка к действующей сессии, настройки уведомлений и заглушение чата. Есть уведомления о новых сообщениях, звонках и добавленных реакциях. Упоминание распознаётся как отдельное слово `@username`. Изменение уже существующей реакции пока не создаёт новое уведомление.
- Service Worker показывает системное уведомление и открывает чат/сообщение. Разрешение запрашивается только по нажатию в настройках. Принятие push провайдером не считается доставкой сообщения: доставка и прочтение подтверждаются клиентом и хранятся на сервере.
- Компактный AI-инструмент для текущего черновика, десять действий, предпросмотр, замена/повтор/отмена. Самостоятельной отправки нет. Нужен настроенный AI-провайдер; тест интерфейса использует контролируемый ответ.
- Подтверждение исходящих аудио/видеозвонков в общем маршруте запуска, защита от повторного нажатия. Отмена не обращается к API создания звонка.
- Новая SVG-иконка настроек из Lucide. Profile Studio с живым предпросмотром, фоном, цветом, emoji-паттерном, ползунками, рамками, эффектами, сроком статуса и серверными пресетами. Сохранение явно отделено от редактирования. Публичный профиль использует сохранённое оформление и серверную приватность.
- Централизованные capabilities для новых возможностей оформления; доступ проверяет backend. Старые проверки VIP ещё не полностью перенесены в capabilities. При окончании VIP сохранённые параметры не уничтожаются, платное оформление отключается при публичном показе.
- Три новых демонстрационных пака: 12 рисованных котов, 12 объёмных роботов, 8 SVG-сцен разработчика. Коты и роботы статические; анимированы части SVG-сцен. Старые паки скрыты из каталога, но прежние сообщения и файлы сохранены. Новые паки содержат разные сюжеты, а не перекрашенные копии.
- Рекомендации стикеров по ключевым словам черновика, избранное/недавние/свои/установленные, удержание для просмотра, обложка и порядок пака, GIF-раздел. Редактор: текст, emoji, обводка, тень, обрезка, отмена. Удаление фона — заливка по сходному цвету, **не нейросетевое выделение сложного объекта**.
- Загружаемые GIF/MP4/WebM нормализуются FFmpeg в ограниченный анимированный WebP и статичный PNG-постер. Невидимые анимации останавливаются, есть бюджет одновременного воспроизведения и reduced-motion. Специальные стикеры запускают короткий эффект по нажатию.
- Отображаемый лимит загрузки берётся из серверной конфигурации, по умолчанию 64 MB, вместо недостоверных 2/4 GB.

## Настройка запуска

1. Сделать резервную копию существующего DATA_DIR. Миграции добавляют таблицы/индексы, не удаляют сообщения.
2. Node.js 24+, `npm ci --ignore-scripts`. Для анимаций нужен FFmpeg/ffprobe; Dockerfile устанавливает их.
3. Сохранить постоянный DATA_DIR на диске. Текущая SQLite-архитектура рассчитана на один постоянно работающий экземпляр. Бесплатный спящий сервер не обеспечивает своевременный push. Горизонтальное масштабирование потребует общей БД и очереди.
4. Один раз создать пару VAPID-ключей: `npx web-push generate-vapid-keys`. Задать `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (действительный `mailto:` или HTTPS контакт) в окружении сервера. Не коммитить приватный ключ и не генерировать новую пару при каждом запуске. Смена пары требует переподписки устройств.
5. HTTPS обязателен вне localhost. На iPhone пользователь устанавливает PWA на экран «Домой», открывает её и включает уведомления в настройках Cipherion.
6. Настроить существующий AI-провайдер отдельно; `AI_API_STYLE=chat` поддерживает Chat Completions. Ключи не выдаются клиенту.

В Notification Service есть реестр провайдеров, но APNs и FCM для нативных приложений ещё не реализованы. Web Push через браузерный FCM endpoint работает через web-push, это не нативный Android adapter. Аватар отправителя в системном уведомлении пока заменён иконкой приложения. Звук/вибрация зависят от возможностей платформы.

## Проверки и пределы подтверждения

`npm run check` и `npm test`: 37 тестов проходят. Проверены настоящие HTTP-запросы двух/трёх аккаунтов, права доступа, параллельные повторы client ID, подтверждение получения, восстановление БД после перезапуска, сохранение оформления и просмотр другим аккаунтом. Проверены восстановление IndexedDB-очереди и повтор после потерянного ответа. Выполнено настоящее перекодирование GIF через FFmpeg. DOM-тесты проверяют AI, подтверждение звонка и сохранение редактора.

Тест очереди push использует подставной провайдер: он проверяет приватность, повторные попытки и удаление истёкших подписок, **не доставку Apple/Google/Mozilla**. Автоматические тесты не заменяют семь пользовательских сценариев на реальных устройствах. Визуальный браузерный запуск в рабочем окружении заблокирован ограничением системных сокетов; сравнение иконок и экранов на iPhone/Android/планшете, светлая/тёмная темы визуально не подтверждены.

Перед выпуском вручную проверить:

- A и B онлайн: сообщение появляется без перезагрузки; редактирование, удаление, реакции и прочтение обновляются.
- B закрывает установленную PWA и блокирует iPhone: A отправляет сообщение, приходит системное уведомление. Нажатие открывает нужный чат и сообщение, в том числе вне последних 60 сообщений.
- B возвращается после офлайна и получает пропущенную историю. Повторять отключение сети во время отправки: одна запись на сервере.
- B читает на телефоне: состояние видно на компьютере. После перезапуска сервера история сохраняется.
- Каждая настройка профиля: изменить → сохранить → перезагрузить → открыть на втором устройстве и другим аккаунтом; отдельно проверить активный/истёкший VIP.

## Что остаётся в исходном задании

Не реализован весь список VIP 2.0. Остаются музыка профиля, полноценное переключение аккаунтов, расширенные папки и правила, законченный редактор тем чатов, главы голосовых/удаление пауз, новые возможности записи видеокружков, полная библиотека custom emoji и все тематические паки, артикулированная анимация растровых персонажей, нейросетевое удаление фона, платёжная интеграция, нативные APNs/FCM, полная миграция старых VIP-проверок на capabilities. Новая реализация grounded summary/естественного поиска с гарантированными ссылками на каждое утверждение также не входит в этот этап: существующий AI не следует считать выполнением всех этих требований.

Новый Studio пока не предоставляет отдельные элементы управления для каждой запрошенной VIP-возможности (например, музыка и загрузка видеоаватара). Не каждый исходный пункт пользовательского задания прошёл полный цикл проверки. Выпуск остаётся черновиком до устранения этих пробелов и реальной проверки системного push.
