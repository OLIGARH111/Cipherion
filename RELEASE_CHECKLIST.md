# Cipherion Release Candidate — проверка готовности

Дата: 2026-10-02. Основа: `a01d37ea689a37907385cc4e84b41f52077fa8e0`.

**Общий статус: ❌ BLOCKS RELEASE.** Это первый проверенный этап подготовки, не завершённое Release Ready Update. Production не переключён и его backup не получен. Успешные локальные тесты не доказывают работу внешних провайдеров и реальных устройств.

## ✅ READY — подтверждено в локальной тестовой среде

- `npm run check`: успешно. `npm test`: **42/42**, без пропущенных тестов, Node 24.19.0.
- Существующие тесты прав чатов/файлов, приватности, семейных ограничений, админ-доступа, VIP/промокодов, AI-изоляции, историй и опросов сохранены.
- Повтор одного запроса отправки с одинаковым `clientId` создаёт одно сообщение, в том числе при шести одновременных HTTP-запросах. Новая запись fingerprint отклоняет повтор ключа с другим содержимым (409), включая повтор после перезапуска.
- Два аккаунта и две сессии получателя: поиск, профиль, чат, доставка/прочтение, файл, выход/повторный вход. Третий аккаунт не получает чужой чат или приватный файл.
- Восстановленная копия тестовой БД и файлов запускается отдельно; сообщения, сессии и файлы читаются. Испорченный backup отклоняется.
- `/health` делает запрос к БД, при ошибке отвечает 503 без внутренней информации.
- Добавлены версия миграции 1, транзакционное применение, индексы и автоматическая локальная копия старой БД до нового этапа миграции.
- Подтверждённый при включении 2FA TOTP больше нельзя повторно использовать для входа. Добавлен лимит попыток по username в дополнение к существующему лимиту IP.
- VIP вычисляется сервером: Free, Active, Expired, Cancelled (все выдачи отозваны), Gifted, Lifetime. Будущие выдачи не дают права заранее. Это не платёжный биллинг.
- Получение прав администратора записывается в audit log; VIP-действия уже имели отдельный аудит.
- Выход/отзыв сессии сразу удаляет её push-подписки.
- Ошибки общего API-клиента при потере сети и не-JSON ответе стали понятными; статус HTTP сохраняется для очереди повторных отправок.

## Известные ограничения и ошибки

- Успешный restart с тем же каталогом данных не равен успешному redeploy Render.
- Нет гарантий сохранности данных текущего production до инвентаризации и внешнего backup.
- Списки и сообщения используют несколько запросов на элемент; полный N+1 аудит не выполнен.
- Нет общего удаления неиспользуемых медиа: безопаснее сохранить файл, чем удалить объект, на который ещё ссылается пересылка/профиль/история.
- Видеосвязь, push и мобильный UI нельзя признать проверенными на основании server integration-тестов.
