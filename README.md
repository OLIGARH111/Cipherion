# Cipherion

Русскоязычный веб-мессенджер с изумрудным интерфейсом Liquid Glass, настоящими аккаунтами, серверным хранением и доставкой событий в реальном времени.

Это первый функциональный выпуск 0.1.0, а не завершение всего расширенного ТЗ. Статус возможностей и недостающие части перечислены в [docs/STATUS.md](docs/STATUS.md).

## Запуск

Нужен Node.js 24 или новее. Устанавливать npm-зависимости не требуется.

```sh
node server/index.js
```

Откройте http://127.0.0.1:3000. Создайте два аккаунта в разных профилях браузера / обычном и приватном окне, найдите второго пользователя по username и начните разговор. В приложении нет предзаполненных пользователей, чатов или сообщений.

```sh
node scripts/check.js
node --test tests/*.test.js
```

Для конфигурации скопируйте `.env.example` в `.env`, заполните нужные параметры и запустите:

```sh
node --env-file=.env server/index.js
```

Пароли от тестовых аккаунтов, ключи провайдеров и содержимое `data/` не входят в репозиторий. Восстановление забытого пароля пока не реализовано: не используйте этот выпуск как единственный канал критически важного общения.

## Render

В корне есть готовый `render.yaml`. В Render выберите **New → Blueprint**, подключите `OLIGARH111/Cipherion` и подтвердите план `starter`: файл создаёт web service `cipherion`, persistent disk 1 GB в `/app/data`, `COOKIE_SECURE=1` и health check `/health`.

Render не сохраняет локальные файлы бесплатного сервиса после рестарта. SQLite и медиа Cipherion требуют persistent disk, который Render предоставляет только на платном web service; сервис с таким диском всегда однокопийный. Подробнее: [Render Blueprint docs](https://render.com/docs/blueprint-spec) и [Persistent Disks](https://render.com/docs/disks).

## Что работает

- Регистрация, вход, сессии HttpOnly, профиль с именем, аватаром и bio, поиск по username / имени.
- Личные чаты, группы, каналы; текст, изображения, видео и файлы до 50 МБ.
- Настоящие события через SSE; сообщения сохраняются в SQLite и переживают перезапуск сервера.
- Ответы, пересылка, редактирование, удаление для всех, закрепление, доставка / прочтение и «печатает…».
- Опросы с одним или несколькими ответами; сервер исключает повторный учёт одного голоса.
- Голосовые и видео-кружочки через MediaRecorder: короткое нажатие переключает режим, удержание записывает, сдвиг влево отменяет, вверх закрепляет. Есть явные кнопки отмены, закрепления и отправки. Запись ограничена тремя минутами.
- Аудиоплеер с перемоткой и скоростью 1× / 1.5× / 2×. Полоски waveform пока декоративные, не анализ сигнала.
- Подключаемая расшифровка аудио / видео с отдельным подтверждением передачи записи провайдеру.
- Роли группы, индивидуальные разрешения, временные ограничения, блокировки, теги, передача владения и журнал действий. Авторизация проверяется сервером, а не только интерфейсом.
- WebRTC-звонки, сигналинг через авторизованные API, групповой mesh до 6 участников, переключение камеры / микрофона, выбор устройств, сворачивание, демонстрация одного экрана и история вызовов.
- 10 тем, пользовательский фон / акцент / текст, настройки стекла, фото приложения и навигации, режимы навигации «стекло / цвет / градиент / фото», автооценка контраста фотографии.
- Архив и закреплённые чаты, уведомления и настройки отдельных чатов, управление сессиями и блокировками.

## Архитектура

```text
public/             ES modules, адаптивный интерфейс и дизайн-система
  app.js            аккаунт, навигация, чаты, запись медиа, SSE
  calls.js          WebRTC, устройства и демонстрация экрана
  groups.js         интерфейс администрирования групп
  settings.js       профиль, темы и настройки
  ui.js             безопасный вывод текста и общие UI-функции
server/
  index.js          HTTP API, сессии, доступ к файлам, SSE, сигналинг
  db.js             SQLite-схема и индексы
  permissions.js    проверка ролей и индивидуальных разрешений
tests/              проверки правил и интеграционные сценарии API
docs/               эксплуатация и статус требований
```

Клиент использует нативные ES modules без сборщика. Сервер использует встроенные API Node.js: `node:http`, `node:sqlite`, `node:crypto`. SQLite работает в WAL-режиме. Выбранная архитектура предназначена для одного серверного процесса; при горизонтальном масштабировании потребуются общая БД, событийная шина и объектное хранилище.

SSE доставляет события, POST API отправляет сообщения. После восстановления соединения клиент перечитывает актуальные сообщения из БД. Это настоящий real-time обмен, хотя WebSocket в этом выпуске не используется.

## Звонки и расшифровка

Камера, микрофон и демонстрация экрана требуют HTTPS (localhost разрешён браузерами для разработки). Для работы через разные NAT / мобильные сети настройте собственный TURN через `ICE_SERVERS`. В production выдавайте короткоживущие TURN credentials: этот выпуск передаёт конфигурацию ICE авторизованному клиенту.

Медиапотоки WebRTC защищены DTLS-SRTP. Сервер приложения передаёт сигналинг и не записывает разговоры или демонстрацию экрана. Текстовые сообщения и загруженные вложения **не имеют сквозного шифрования** и доступны оператору серверного хранилища.

Для расшифровки задайте `TRANSCRIPTION_URL`, `TRANSCRIPTION_KEY`, `TRANSCRIPTION_MODEL` совместимого с multipart audio-transcriptions сервиса. Провайдер должен принимать выбранный браузером формат WebM / MP4. Ключ хранится только на сервере. Без конфигурации интерфейс сообщает, что сервис не подключён; выдуманных расшифровок нет.
